# AGENTS.md

## Project overview

A lightweight browser game that teaches inexperienced drivers correct motorway and expressway driving under Polish traffic law: keeping right, signalling lane changes, and keeping the legal following distance (half the speed in km/h, in metres). Short 90-second sessions, two modes (learn with live hints, exam without), scoring with supportive verbal feedback, local result history. Built with **Godot 4.x / GDScript** and exported to **Web (WebAssembly + WebGL 2)**.

The source of truth for scope and behaviour is [`wymagania-symulator-autostrady.md`](wymagania-symulator-autostrady.md) (Polish). Its markers mean: **[DECYZJA]** fixed requirement, **[PROPOZYCJA]** default that may change, **[PARAM]** value that must live in config, **[OTWARTE]** unresolved — implement the default and mark the code `# TODO(open):`.

**Decisions take precedence:** the MVP spec [`.ai/specs/2026-10-11-highway-driving-simulator-mvp.md`](.ai/specs/2026-10-11-highway-driving-simulator-mvp.md) resolves the requirements doc's [OTWARTE] items in its *Decisions* table and defines the architecture and phasing. Where the two disagree, the spec wins; use `# TODO(open):` only for questions neither document settles.

## Task routing

| When the task involves… | Read first | Key rules |
|---|---|---|
| Project skeleton, `project.godot`, export, CI | requirements §3, §17 step 1; `project.godot`, `export_presets.cfg`, `.github/workflows/ci.yml` | Renderer **Compatibility** (WebGL 2) only — no Forward+/Mobile-only features. Single-threaded web export (no COOP/COEP, no `SharedArrayBuffer`). Pin the Godot version in `project.godot` and README. `.tscn`/`.tres` in text format. |
| Simulation core: vehicles, lanes, lane queries | requirements §4.3, §8.4, §15.2; `core/sim/` (`TrafficSim`, `VehicleState`, `PlayerCommands`, `LaneQuery`, `LaneIndex`, `InputLog`) | Pure GDScript classes with **no scene or rendering dependencies** (a test scans `core/`). Logical coordinates only (longitudinal `s` in metres at the body centre, lane index / lateral offset). Fixed-step `_physics_process`; the only RNG is `TrafficSim.rng`, seeded at construction — seed + `InputLog` replays a session exactly. Free-lane, gap, overtaking and signal checks go through `LaneQuery`, never re-implemented; its neighbour queries read `TrafficSim.lanes` (a `LaneIndex` of per-lane lists sorted by `s`), so add vehicles and change lanes only through `TrafficSim`. The player is a `VehicleState` like any AI car. |
| Traffic AI and spawning | requirements §7, §10; `core/ai/` (`Idm`, `AiDriver`), `core/sim/spawner.gd` (`Spawner`); tunables in `SimConfig`, levels in `config/difficulty_levels/` | IDM-style car-following, simplified MOBIL lane changes weighed every `ai_lane_decision_interval_s`. AI and the spawner use the **same** `is_lane_free` / `min_gap` functions as scoring. Never spawn into or near a collision: skip a spawn rather than force it; during a session spawn only beyond view. Vehicles are pooled by `TrafficSim` (`remove_vehicle` / add), no create/free churn. |
| Scoring, event log and session record | requirements §8, §13, §16 (Ocenianie); `core/scoring/` (`ScoringSystem`, `EventLog`, `ScoreEvent`, rules in `core/scoring/rules/`, `SessionRecord`, `SessionRecordBuilder`, `ExamCalibration`), `core/ai/ideal_driver_bot.gd`, `ScoringConfig` + `config/scoring.tres`, `DifficultyLevel.exam_pass_score` | Scoring **observes** the simulation, never mutates it: `ScoringSystem.observe(dt)` runs after each `TrafficSim.step(dt)`; rules read the sim and write only to the `EventLog`, and use `LaneQuery` for every gap / free-lane / overtaking / signal check. Every rule K1–K4 / N1–N3 has unit tests mirroring the acceptance criteria. Continuous events are aggregated into segments, not logged per frame. Rules hold the sim, config and log — never the `ScoringSystem` (no reference cycles). Changing weights, traffic or AI moves the bot's score: re-measure `exam_pass_score` (the calibration test prints the new values). |
| Feedback texts, live hints and session summary | requirements §11; `core/feedback/` (`HintEngine`, `Hint`, `SummaryGenerator`, `Summary`, `FeedbackLine`), `FeedbackConfig` + `config/feedback.tres`, `ui/summary_panel.gd` (`SummaryPanel`, `SummaryIcon`), `ui/hint_list.gd` (`HintList`); strings in `i18n/strings.csv` | Rule/template based, no external API. `HintEngine` exists in learn mode only (`SessionManager.hints`, null in the exam): it reads the sim and `ScoringSystem` after each scored step (`observe(events)`), never changes them, and checks gaps, free lanes and overtaking through the scoring rules and `LaneQuery`; cooldown, on-screen cap and duration are in `feedback.tres` and run on sim time. Every hint pairs its text with an icon. Supportive tone, explain the rule ("why"), not just the error. Core picks translation keys with format arguments (`FeedbackLine`), never text; the UI translates (Polish first). Gender-neutral wording only (Q3) — a test lints every Polish string for gendered verb forms. Strength and areas to improve come from category penalties; every description sentence is one template line, 2–4 per summary. |
| Rendering: road, player camera, traffic, mirrors, HUD | requirements §4–§5, §7.1, §14; `game/main.tscn`, `game/world/` (`RoadLayout`, `RoadSegmentMesh`, `RoadView`), `game/player/` (`PlayerView`, `SignalBlink`), `game/traffic/` (`TrafficView`, `VehicleView`, `VehicleLook`, `BrakeLights`), `game/mirrors/` (`MirrorsView`, `Mirror`), `config/view_config.tres`, `QualityPreset` + `config/quality_presets/low.tres` / `high.tres`; `game/perf/` (`FpsProbe`, `LowFpsWatch`) + `PerfConfig` / `config/perf_config.tres`; `ui/` (`Hud`); strings in `i18n/strings.csv` | Presentation only reads simulation state. Vehicle views are pooled per look and follow `TrafficSim.vehicle_added` / `vehicle_removed` — no create/free per spawn; a vehicle's look and colour come from its id, never from an RNG. Floating origin and segment recycling for the infinite road: objects sit at `z = -(s - player.s)`, recycled segments appear only beyond `ViewConfig.draw_distance_m()`. Mirrors are `SubViewport`s sharing the main `World3D` (no own world), rendered at the preset's resolution scale and frame interval, flipped left-right on screen; their range (`ViewConfig.mirror_range_m()`) stays within the road kept behind and the spawner's hidden zone. With mirrors off none is built. A session's draw distance comes from its preset via `ViewConfig.for_quality` (a copy — never mutate the shared `.tres`). The learn-mode HUD alone shows the live score and the blind-spot warnings (icon + text, never colour alone; zone in `ViewConfig.blind_spot_*_m`) — the exam shows neither (Q10, Q11). Budget: 60 FPS target / 30 FPS min on integrated GPU, package ≤ 50 MB; measured with `perf=1` by the README's method (only driving frames are sampled). |
| Session flow | requirements §9.3; `game/session/` (`SessionManager`, `LaunchOptions`, `DevLauncher`); `SimConfig.countdown_s` / `session_length_s` / `respawn_*`; `core/sim/respawn.gd` (`Respawn`); `config/dev_launcher.tres` | `SessionManager` owns the sim and is the only node that steps it: `INTRO` (countdown, sim frozen, input dropped) → `DRIVING` ⇄ `RESPAWNING` (learn only) → `ENDED`, with `paused` orthogonal to `INTRO` / `DRIVING` / `RESPAWNING` (`pause` / `resume` / `toggle_pause`; while paused `step` does nothing; `NOTIFICATION_APPLICATION_FOCUS_OUT` or `NOTIFICATION_WM_WINDOW_FOCUS_OUT` pauses, focus returning does not resume; `physics/common/max_physics_steps_per_frame` caps catch-up), with an `end_reason` (`TIME_UP`, `COLLISION`, `OFF_ROAD`) and its §13 `status()` (`completed` / `aborted_collision` / `aborted_offroad`). The session carries the launch `mode`: in the exam a player collision or leaving the road ends it at once as aborted and the HUD names the cause (§9.2); in learn mode it starts a respawn instead: K4 is charged, the sim freezes and input is dropped for `respawn_fade_s` while the HUD fades and names what happened, the player is put back at the fade's midpoint through `Respawn` (nearest free window on the right lane via `LaneQuery.is_lane_free` with no slower vehicle just beyond it, else the vehicles in the window are despawned; `TrafficSim.place_vehicle`; `ScoringSystem.restart_after_respawn`), and the timer runs on — time-up still ends the session. A respawn moves the player outside `TrafficSim.step`, so a learn session with a respawn replays through `SessionManager` (seed + the commands fed while `DRIVING`), not `TrafficSim.replay` alone. AI–AI collisions are despawned silently by the `Spawner`, never charged. `start` attaches a `Spawner` for the launch options' `DifficultyLevel`. With a `scoring_config` (set in `game/main.tscn`) it runs a `ScoringSystem` after every sim step and builds the `SessionRecord` at the end; `main.gd` saves it through `SaveManager`. With a `feedback_config` (also set there) it also builds the `summary` the HUD's end screen shows. Views and the HUD only read its state. Until Phase 10 menus, `DevLauncher` turns URL params (web) or user args (desktop) into `LaunchOptions` (mode, profile, level and its `DifficultyLevel`, seed, `QualityPreset`, mirrors on/off, FPS probe on/off); invalid or missing values take the config default (`high`, mirrors on, probe off). |
| Input | requirements §6; `game/player/player_input.gd` (`PlayerInput`), `game/main.gd` | Actions defined in the Godot **Input Map**, never hard-coded keys. `PlayerInput` turns action events into one `PlayerCommands` per physics step; the `pause` action is handled by `main.gd` (`SessionManager.toggle_pause`), not as a driving command. |
| Persistence and history | requirements §13; spec Data Model: Persisted, Edge Cases; `persistence/` (`HistoryStore`, `save_manager.gd` = the `SaveManager` autoload), `PersistenceConfig` + `config/persistence.tres` | `user://` (IndexedDB on web). ## Code conventions

- GDScript with **full static typing**: typed variables, parameters, and return types (`var speed: float`, `func min_gap(speed_kmh: float) -> float`).
- Cross-node communication through Godot signals (`lane_change_started`, `lane_change_finished`, `collision`, `score_event_emitted`, `session_ended`). Autoloads only for global services (`Config`, `SaveManager`, optionally `EventBus`).
- Language: code, comments, commits, PRs, and issues in **English**; player-facing UI text in **Polish**, via translation files.
- No personal data collection, no accounts, no external telemetry.
